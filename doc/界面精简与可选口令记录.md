## 界面变化

- 下拉框仅提供 Tomato、Block、RowPixel、PerPixel、PicEncryptRow、PicEncryptRowColumn、Sort、Random，默认 Tomato。
- 删除强度下拉框、相关事件、内存复用和声明窗口代码。
- 旧多尺度图可自动识别并显示“旧版图片（仅还原）”，下拉框锁定；切回混淆时自动选择 Tomato，不再提供旧算法的新建入口。
- 单图处理结果需要先保存 PNG，再通过“选择图片”重新打开来还原。
- 口令标签和提示随混淆/还原/批量/兼容状态变化。无口令图片还原时禁用不需要的口令输入，有口令图片明确提示需要原口令。
- 批量仍保留目录层级、自动编号、输出树排除、停止和失败继续功能。

## 格式及可选口令

### 有口令

- 有口令的新移植算法继续使用 v2，不改动旧字段或密钥派生方式。
- 旧多尺度 v1 也不改动，原有固定像素和元数据指纹继续检查。
- 旧 v1/v2 图片始终需要正确原口令；新版工具不应因“口令可选”而错误允许绕过。
- 口令本身不写入 PNG；空格不自动删除，只输入空格仍算设置口令。

### 无口令

- 仅在用户确实输入空字符串时采用新的 PNG 元数据 v3，明确标记 `key_mode=none`。
- 用公开 16 字节随机盐和固定域 `confusing-images/public-parameters/v1` 通过标准 SHAKE-256 生成置换及校验参数。
- 不设置隐藏默认口令，也不要求用户另存密钥。公开派生没有秘密，不必执行针对口令猜测的慢速 PBKDF2。
- 还原时先严格检查模式、版本和字段，再从图内公开参数还原，并比较载荷和原像素校验。
- 输入框里残留的其他图片口令不会影响无口令图片；混合批量中，公开图片自动处理，有口令图片使用输入口令。
- v3 新格式需要 v0.4.0 或更新工具读取，旧版 EXE 不认识该格式。
- **任何持有完整无口令 PNG 的人都能还原。** 此模式不保密，公开参数下的校验只能帮助检查普通损坏，不提供防恶意伪造的认证。视觉混淆本身也不等于现代加密。
- 固定 v3 像素和元数据指纹，防止后续无意改变公开参数派生导致旧图不兼容。

### 原项目兼容模式

- 不改动原项目要求。Tomato/PicEncrypt 仍需要有效数值；字符串算法按原密钥处理。
- Sort 无需密钥；Random 原格式还原依据末行映射，不验证种子。
- 本次“口令可选”不代表为原项目格式偷偷填入默认参数，避免破坏既有互通。

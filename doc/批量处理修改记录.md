# 文件夹批量处理 / v0.3.0

## 2026-10-21 需求与确认

1. 新增路径选择，递归处理所选目录下的图片。
2. 结果保存到所选根目录下新建的 `confusing_images`。
3. 输出保留相对目录层级，统一保存无损 PNG。
4. 用户确认重名时自动编号，不覆盖旧结果。
5. 用户授权备份、修改、测试和重新打包，保留旧 EXE；不提交或推送 Git。

示例：

```text
D:\图片\人物\二级\a.jpg
→ D:\图片\confusing_images\人物\二级\a.png
```

## 备份与实现范围

- 修改前备份源码、测试、工具、文档和 v0.2.0 EXE 到 `doc/backups/before-batch-20261021-164115.zip`。
- 继续使用既有 Tkinter、Pillow、NumPy，无新增依赖。
- 新版交付命名为 `ConfusingImages-0.3.0.exe`，旧版本不覆盖。
- 批量沿用当前混淆/还原、算法、强度、口令和兼容模式。
- 本工具 PNG 批量还原逐张读取元数据，可在同一目录混用 v1/v2 和不同算法。
- 参考图片和用户测试图片不修改，也不拿来生成公开演示图。

## 扫描与路径映射

- 选择目录阶段只读扫描，不创建输出目录，也不写图片。
- `BatchPlan` 保存根目录、固定输出根、相对图片路径及扫描问题快照。
- 支持 `.png/.jpg/.jpeg/.bmp/.webp`，扩展名忽略大小写；实际解码继续复用原来的格式、动画和尺寸检查。
- 排除根输出目录 `confusing_images` 的整个子树，重复执行不会扫描自己的结果。
- 符号链接、Windows 目录联接及其他重解析点跳过，避免环路和越出所选路径；云占位等带此属性的条目也可能跳过，界面会显示数量。
- 扫描失败的子目录记录为扫描问题，不悄悄当作已成功处理。
- 图片按相对路径排序，逐张处理，避免同时展开整个目录的图片。
- 批量还原时需要选中实际存放混淆 PNG 的文件夹，还原输出仍是这次所选文件夹下的 `confusing_images`，不会覆盖混淆图片。

## 保存与失败隔离

- 沿用 `save_png` 的同目录临时写入和原子提交。
- 新增 `overwrite=False`：Windows 使用禁止覆盖目标的 `os.rename`；非 Windows 用原子排他硬链接提交。原有单图保存的默认覆盖确认语义保持不变。
- 重名使用 `a.png`、`a_2.png`、`a_3.png`，包括不同扩展名碰撞、已有文件、已有同名目录和保存期间出现的竞争文件。
- 发生检查之后的竞争重名时，底层抛出 `FileExistsError`，批量改用下一编号，不破坏竞争进程创建的文件。
- 写入前检查输出根及子目录不是文件、符号链接或重解析点；输入快照重新验证相对路径和链接状态。
- 单张解码、变换、保存或内存失败计入失败后继续；失败目标不会作为成功结果登记。
- 每张图片完成后关闭输入和结果对象，尽快释放像素内存。
- 含本工具参数的 PNG 在批量混淆/原项目兼容处理中拒绝再次处理，避免覆盖内层还原参数；应选择本工具还原模式。
- `BatchResult` 在内存保存统计、失败原因和输入/输出映射，不写日志文件，也不记录口令。

## 界面和停止操作

- 新增“选择文件夹”“停止批量”“批量详情”。原“选择图片”功能保留，再次选择单图即退出目录模式。
- 目录预览仅显示数量及说明，不在 UI 中载入所有图像。
- 开始前确认操作、数量、输出路径、算法和兼容风险。
- 文件级进度映射为总进度，后台任务继续复用原消息队列，所有 Tk 控件只在主线程更新。
- 停止采用事件请求，只在图片之间检查；当前图片处理和原子保存结束后才停止。已完成结果保留，尚未尝试的不计为失败。
- 停止后的进度按实际已尝试数量显示，不误报为 100%。
- 自动保存后手动“保存 PNG”保持禁用，避免混淆单图和批量的保存语义。
- 完成弹出统计，可查看批量详情；没有额外输出日志文件。

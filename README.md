# 混淆图工具 / Confusing Images

一个离线运行的 Windows 图片小工具。支持从 [ObfuscationUtils](https://github.com/2195517546/ObfuscationUtils) 移植的八种算法，以及文件夹递归批量处理。

**v0.7.0：** 选择文件夹后左侧展示可勾选的图片文件列表（文件名+相对路径），支持全选/逐行勾选，仅处理勾选图片；输出仍到 `confusing_images` 子目录保持层级。保留 v0.6.0 的多次混淆/逐层还原、多线程并行、可选口令和放开限制。

## 功能

- 中文图形界面，输入/结果双图预览。
- 八种算法支持任意长宽及奇数尺寸，不再显示旧版强度设置。
- 口令可选，不需要单独保管参数文件；设置口令后仍需相同口令还原。
- PNG 保存还原参数，校验完整性和还原像素，有口令图片额外校验口令。
- 支持 Pillow 可解码的静态图片（按内容识别，不受来源、扩展名或固定尺寸限制）；结果统一保存为 PNG。
- 支持透明图片，自动校正 EXIF 方向，保留 ICC 颜色配置。
- 后台线程处理图片，不上传文件、不保存口令、不自动覆盖输入图片。
- 八种移植算法：Tomato、Block、RowPixel、PerPixel、PicEncryptRow、PicEncryptRowColumn、Sort、Random。
- 两种明确区分的模式：带校验的本工具 PNG / 可与原 Java 项目互通的无参数 PNG；无参数图片也可按所选算法手动尝试还原。
- 选择文件夹后递归批量处理，自动保存到其下 `confusing_images`，保留所有相对层级，重名自动编号、不覆盖旧结果。

## Windows 使用

双击 `ConfusingImages-0.7.0.exe`，目标电脑无需安装 Python 或 Java。旧版 EXE 保留，可自行区分版本。

1. 点击 **选择图片**。
2. 选择 **混淆图片**，选择算法（默认 Tomato）；口令可以留空，也可以自行填写。
3. 点击 **开始混淆**，完成后点击 **保存 PNG**。
4. 还原时选择保存的混淆 PNG，程序会自动切换到 **还原图片**。
5. 无口令图片直接点击 **开始还原**；有口令图片输入生成时相同的口令，再保存结果。
6. 多次混淆后，**点一次还原一层**，可停在中间层查看，继续点击逐步回到原图。

要还原刚生成的结果，请先保存，再通过“选择图片”打开该 PNG。修改口令、算法或操作模式会丢弃尚在右侧显示的旧结果，请先保存需要的图片。

快捷键：`Ctrl+O` 选择图片，`Ctrl+Enter` 开始处理。也支持将图片拖到 EXE 文件上，由 Windows 将路径作为启动参数传入；不支持将文件拖进窗口。

### 文件夹批量处理

1. 点击 **选择文件夹**，等待扫描完成。包含其下所有子目录中的 PNG、JPG/JPEG、BMP、WebP，大小写扩展名均支持。
2. 扫描后左侧会列出所有图片（文件名 + 相对路径），可**逐行勾选**或点击 **全选 / 全不选**。
3. 选择 **混淆图片** 或 **还原图片**，选择算法和兼容模式，口令可留空。本工具 PNG 批量还原会逐张自动识别算法和口令要求；有口令图片使用输入的口令，无口令图片直接还原。
4. 点击 **开始批量混淆/还原**，只处理已勾选的图片，确认图片数量、操作方向及输出路径后执行。
5. 结果自动保存，无需点击“保存 PNG”。完成后弹出统计，可通过 **批量详情** 查看失败原因及输入/输出对应关系。
6. 需要停止时点击 **停止批量**：先完成当前图片的处理和保存，再停止，不删除已完成结果。点击“选择图片”可回到单图模式。

例如选择 `D:\图片`：

```text
输入                                  输出
D:\图片\a.jpg                         D:\图片\confusing_images\a.png
D:\图片\人物\b.webp                   D:\图片\confusing_images\人物\b.png
D:\图片\人物\二级\c.png               D:\图片\confusing_images\人物\二级\c.png
```

- 输出统一为完整 PNG；文件名主体保留，重名自动使用 `a_2.png`、`a_3.png`，包括不同输入扩展名冲突和多次执行产生的冲突。
- 选择目录时只扫描，不创建输出目录。原图和旧结果不覆盖；保存时也检查竞争出现的同名文件，自动改用下一个编号。
- 所选根目录下的 `confusing_images` **整个输出子树不参与扫描**，避免反复混淆结果。符号链接和 Windows 目录联接也跳过，避免循环和越出所选目录；输出目录被链接或普通文件占用时拒绝写入。
- **批量还原时请选保存混淆 PNG 的结果目录**。还原图片仍按约定保存到这次所选目录下新建的 `confusing_images`，不会覆盖混淆图。
- 单张损坏、错误口令、不支持的动画或保存失败会计入失败后继续。未完成的文件不当成成功；详情仅保存在本次程序内存中，不生成额外日志或记录口令。
- 批量支持**多次叠加混淆**：再次混淆含参数的 PNG 时，会把上一层参数链式保存；还原时每点一次回退一层。
- 批量采用**多线程并行**（默认按 CPU 核数，最多 32 线程）并缓存曲线路径，Tomato 等算法大批量处理显著提速；会按线程数成倍占用内存，超大图较多时注意可用内存。开始前会使用当时扫描到的文件快照；新增文件需要重新选择文件夹扫描。

### 本工具 PNG 模式（默认）

不要勾选“原项目兼容模式”。八种算法均支持以下两种方式：

- **留空口令**：内部参数根据公开随机盐产生并随 PNG 保存，任何持有完整 PNG 的人都可直接还原。参数采用 v3 格式，需要 v0.4.0 或更新版本工具读取。
- **填写口令**：继续使用原有 v2 格式，由口令和随机盐派生参数，必须使用相同口令还原；口令本身不写入图片。

还原时自动识别两种格式。无口令图片不会误用输入框中残留的其他口令；有口令图片不会因为留空而绕过校验。旧 v1 多尺度图片继续由内部兼容逻辑自动还原，界面只显示“旧版图片（仅还原）”，不再提供该算法的新建入口。空格不自动删除，输入空格仍算设置了口令。

**无口令模式不保密，其校验只用于检测普通损坏，不具备防恶意伪造的认证能力。** 单图和批量均遵守这一规则。混合批量还原时，未填口令会导致有口令图片计为失败，无口令图片仍可成功。

- Block 固定 32×32 块，必要时补边；本工具记录原尺寸，还原后自动裁回。
- Sort 的列映射放在 PNG 参数中，不覆盖末行；Random 可从派生参数重建列顺序。两者均保留末行和透明度。
- Sort 依赖首行色值：首行颜色全部相同或已经排序时，列顺序可能不变，效果不明显属于原算法特性，不代表处理失败。
- **这种模式的口令和像素格式不是原 Java 兼容格式**，不能把任意口令直接交给原 Java 工具解混淆。

### 原项目图片互通

处理原 Java 项目生成的图片，或准备将结果交给它还原时：

1. 勾选 **原项目兼容模式（无 PNG 校验）**。
2. 手动选择正确的算法及混淆/还原方向，载入完整 PNG。
3. 按下表输入原项目密钥，再开始处理；保存完整 PNG，不转为 JPEG，不删除 Alpha 通道。

| 算法 | 兼容密钥 | 说明 |
|---|---|---|
| Tomato | 有限数值，如 `0.618`、`114514` | Gilbert 曲线循环位移，支持负数 |
| Block | 任意字符串 | 原项目默认 32×32 块；补边尺寸不会自动裁回，因为原格式未记录原尺寸 |
| RowPixel / PerPixel | 任意字符串 | 采用原 MD5 置换，按 UTF-8 编码匹配 |
| PicEncryptRow / PicEncryptRowColumn | `0 < 密钥 < 1`，如 `0.618` | 双精度 Logistic 序列；退化或重复序列明确拒绝 |
| Sort | 不需要密钥 | 原格式末行保存映射，末行颜色和透明度有损 |
| Random | 整数种子或字符串 | 复现 Java Random、String.hashCode；原格式还原实际只读末行映射，不验证种子 |

**兼容模式没有错误密钥检测，也无法验证原图像素。** “处理完成”不表示密钥正确。Sort/Random 的原 Java 实现会把末行 RGB 压为 RGB565、丢失透明度，并存在末行列对应问题；此模式为互通保留原行为，已损失的数据无法找回。仅本工具模式对这两种算法进行无损适配。

“口令可选”仅针对默认的本工具 PNG 模式。原项目兼容模式仍按上表填写数值密钥或字符串；Sort 无需密钥，Random 还原也无需密钥。

兼容范围针对固定原项目版本 `b573e0051d375a7a4c7ccfe7d7e385997b52348b`、默认参数和未修改的完整 PNG。未实现自定义 Block 网格、任意其他工具格式或受损图片修复。PicEncrypt 不照搬原 `Util` 在非法字符串时静默使用默认数值的行为：若原图片使用默认值，请显式输入 `0.114514`（Row）或 `0.1145`（RowColumn）。

### 手动还原无参数图片

选择没有本工具还原参数的图片（例如你手头的 JPG 参考图）并点击“还原图片”时，程序不再拒绝，而是按当前所选算法和密钥尝试还原，结果标记为“未校验”。

- 界面会显示当前算法留空时使用的默认参数：Tomato=`1`、PicEncryptRow=`0.114514`、PicEncryptRowColumn=`0.1145`；字符串算法默认空字符串；Sort/Random 依赖末行映射不验证密钥。
- **“未校验”表示程序无法证明算法或密钥是否正确。** 如果原算法或密钥不对，或图片经过 JPEG 压缩、缩放、裁切、加水印，结果不会是正确的原图，信息损失无法靠取消限制补回。
- 勾选“强制手动尝试（忽略嵌入参数）”可对本工具 PNG 也强制按所选算法尝试，忽略其内嵌参数，同样标记未校验。

### 请务必了解

**这是视觉混淆，不是安全加密。** 颜色统计和部分局部图案仍可能暴露信息，不适合保护敏感资料；口令校验也不能阻止弱口令被离线猜测。口令遗失无法找回。

- **必须保留本工具输出的完整 PNG。** 转成 JPEG、截图、缩放、裁切、编辑像素或删除 PNG 文本参数都会导致还原失败。
- 聊天软件和图片平台可能压缩图片或清除参数。分享时应使用“原文件/文件发送”，并自行验证接收文件是否还能还原。
- 无损还原指**归一化后 RGB/RGBA 八位像素一致**，不是恢复输入文件的原始字节、JPEG 编码、EXIF 或原始调色板。灰度、CMYK、调色板和高位深图片会转成八位 RGB/RGBA。
- 默认模式只还原本工具兼容版本的 PNG；兼容模式仅针对上述固定原 Java 版本。无参数图片手动尝试不保证恢复出原图。
- 不再设置固定像素数或边长上限；能否处理取决于实际可用内存。动画、多页文件需先导出单帧。
- 每次使用新的随机盐保存还原参数；但 Sort 等依赖原图自身排序的算法，像素结果可能相同。
- **多次混淆**：每次混淆会把输入自带的上一层参数保存到新图的 `upper_metadata`（参与完整性认证）。还原时还原一层像素并把上一层参数写回，结果是"上一层混淆图"，可继续点还原。不同算法、不同口令逐层叠加也能逐层回退；旧图无此字段，行为不变。

## 开发环境

Windows 10/11 x64，Python 3.11（需包含 Tkinter）。在项目根目录执行：

```powershell
py -3.11 -m venv .venv
.\.venv\Scripts\python.exe -X utf8 -m pip install -r requirements-dev.txt
.\.venv\Scripts\python.exe -X utf8 main.py
```

Python 使用 `-X utf8`，避免旧版 Windows/pip 按 GBK 读取中文文件。开发依赖只安装在 `.venv`，不修改全局 Python 环境。

测试：

```powershell
.\.venv\Scripts\python.exe -X utf8 -m unittest discover -s tests -v
```

### 打包单 EXE

在项目根目录用 PowerShell 7 执行：

```powershell
pwsh -NoProfile -File .\build.ps1 -Name ConfusingImages-0.7.0
```

脚本先运行回归测试，再生成图标并调用 PyInstaller。最终交付文件：

```text
dist/ConfusingImages-0.7.0.exe
```

只需分发这个 EXE。PyInstaller 单文件程序启动时仍会在系统临时目录解包运行组件，首次启动可能稍慢；这不影响单文件分发。程序未签名，Windows SmartScreen 或杀毒软件可能提示，请仅运行可信来源的版本，不建议关闭安全防护。

打包后的实际启动验证和示例生成：

```powershell
.\.venv\Scripts\python.exe -X utf8 -m tools.validate_release dist\ConfusingImages-0.7.0.exe
```

该命令生成自绘测试图、混淆/还原示例、目录批量示例及测试报告，然后从隔离目录启动 EXE、截取其窗口并关闭；会短暂显示程序窗口。验证产物位于 `doc/validation/`，不提交 Git。

原 Java 对照验证（仅开发验证需要现有 JDK，程序本身不需要）：

```powershell
.\.venv\Scripts\python.exe -X utf8 -m tools.verify_upstream
# 未自动找到 JDK 时：添加 --jdk-bin '你的JDK目录\bin'
```

该命令仅下载固定版本的已审阅 Java 算法，编译最小同步测试夹具，不执行上游 Gradle 脚本。26 组用例逐像素对比 Java/Python 混淆结果，并双向读取彼此的 PNG。固定指纹保存在 `tests/fixtures/upstream-vectors.tsv`，日常回归测试不需要 Java 或联网。

如需要复现本次依赖版本，可安装 `requirements-lock.txt`。EXE 建议上传到 GitHub Releases，而不是提交到源码仓库。

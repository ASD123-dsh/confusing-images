# 连续还原与停止统计修复 / v0.7.1

## 2026-10-23 需求及备份

- 用户要求先核实并修复两处问题，再编译打包 EXE，交由用户手动测试。
- 沿用 Python 3.11、Tkinter、Pillow、NumPy 和 PyInstaller，不增加运行依赖，不改 PNG 格式或算法实现。
- 改动前备份所有 Git 跟踪文件和 v0.7.0 EXE：`doc/backups/before-restore-cancel-20261023-134414.zip`。压缩包内含逐文件 SHA256 清单。
- 在项目 `.venv` 内安装现有 `requirements-lock.txt` 锁定依赖，不修改全局 Python 环境。

## 复现证据

先补测试，再在未修改的业务代码上运行。3 个测试方法产生 5 项断言失败：

1. 三层图片连续点击还原三次，结果仍携带两层参数，证明每次实际重做最外层还原。
2. 外层 Tomato、下一层 PerPixel 时，处理完仍显示 Tomato，未刷新下一层算法与口令要求。
3. 确保两个任务已运行，在第一张完成时停止；第二张分别成功、产生未校验结果、读取失败，三种情形都只统计了第一张（`completed=1`，应为 `2`）。

## 实现

### 单图连续还原

- 增加当前还原进度引用，下一次自动还原使用上一次校验成功的结果；左侧仍保留原始载入图片。
- 逐层刷新算法、口令输入状态和按钮文案，支持有口令、无口令和不同算法混合叠加。
- 修改下一层口令或该层还原失败时，保留上次成功结果和进度，允许保存中间 PNG、更正口令后重试。
- 最后一层成功后显示“已还原至原图”，禁用继续处理，同时阻止快捷键再次处理。
- 重新选图、切换操作模式或强制手动选项时重置进度，从左侧载入图片开始。
- 手动尝试和原项目兼容处理沿用原行为，不自动连续推进；批量每次仍对所选输入还原一层，下一轮需选择新输出目录。

### 批量停止

- 停止只阻止继续提交任务，不再中断结果收集。
- 所有已提交任务完成后，成功、失败、未校验数量及输入输出对应关系全部汇入结果。
- 初始提交阶段也检查停止请求。尚未提交的文件计为未处理，不计失败。
- 界面说明改为等待已提交任务结束并汇总，不再暗示只会多保存一张。

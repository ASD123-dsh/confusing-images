# 多次混淆与批量提速 / v0.6.0

## 2026-10-22 用户确认

1. 支持多次混淆和多次还原，不再限制叠加次数。
2. 多次还原采用“点一次还原一层”语义，可停在中间层查看。
3. 大批量提速采用多线程并行（按 CPU 核数）。
4. 备份、修改、测试并打包新版 EXE；不提交或推送 Git。

## 备份与范围

- 修改前备份源码、测试、工具、文档和 v0.5.0 EXE：`doc/backups/before-chain-parallel-20261022-135603.zip`。
- 不新增运行依赖，不修改全局 Python 环境，不修改 `demo/` 和 `测试图片/`。
- 仅改核心链路、批量执行和界面提示，不改动原 Java 算法兼容性。

## 链式多次混淆

- 混淆时若输入自带本工具参数，把上一层参数原样保存到新图的可选字段 `upper_metadata`，随本次元数据一起参与 HMAC 认证，保证不可被篡改。
- `_parse_metadata` 将 `upper_metadata` 纳入可选字段校验：必须存在时是合法 JSON 对象，否则拒绝继续回退。
- 还原时还原一层像素并通过原像素校验后，把 `upper_metadata` 写回结果；结果仍是带参数的“上一层混淆图”，可继续点还原。
- 无 `upper_metadata` 的旧图行为不变，还原后仍是无参数原图。
- 单图 `scramble_image` 不再被批量层拦截叠加；批量混淆也移除“已含参数禁止再次混淆”的拦截，改为链式保存。
- 支持不同算法、不同口令逐层叠加，逐层回退时各自使用自己的参数。

## 批量并行与缓存

- `run_batch` 从串行改为 `ThreadPoolExecutor` 多线程，默认线程数 `min(32, os.cpu_count())`，可用 `workers` 参数覆盖。
- numpy/Pillow 的像素操作会释放 GIL，多线程能真正并发提速；线程数越多内存占用按比例上升。
- 每个任务独立完成“读→处理→保存→释放”，结果回主线程后统一更新统计，避免共享状态竞争。
- 取消语义：停止后不再提交新任务；已提交的少量任务会完成并保存（不再严格只保存 1 张）。已有结果保留，未提交的文件不处理。
- Tomato 的 Gilbert 曲线路径与密钥无关、只依赖尺寸，新增按 `(width, height)` 的线程安全缓存（上限 64 条，LRU 淘汰），同一尺寸图片只算一次。

## 性能测量

- 1200×900 单张 Tomato 混淆：优化前约 1200 ms（其中 Gilbert 路径生成约 1183 ms），缓存后同一尺寸后续约几十毫秒（8 张平均 178 ms/张，含首次路径生成）。
- 其他算法原本 17～232 ms/张；多线程并行进一步缩短大批量总耗时。
